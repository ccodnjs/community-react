# React 화면 최종 QA 체크리스트

## 1. 목적

이 문서는 `community-frontend-react` 화면을 최종 점검할 때 사용하는 확인용 체크리스트이다.  
기준은 다음 두 가지이다.

1. 기존 HTML/CSS 버전에서 의도했던 화면 분위기와 흐름이 React 버전에서도 유지되는가
2. 백엔드 API와 연결했을 때 실제 기능이 자연스럽게 동작하는가

---

## 2. 점검 전 준비

확인 전에 먼저 아래를 맞춰둔다.

- 백엔드 서버 실행
- React 프론트엔드 실행
- 테스트용 계정 1개 이상 준비
- 가능하면 게시글/댓글/좋아요 데이터가 1개 이상 있는 상태로 확인

추가로 있으면 좋은 것

- 본인 게시글 1개
- 다른 사람이 쓴 게시글 1개
- 이미지가 포함된 게시글 1개
- 댓글이 여러 개 달린 게시글 1개

---

## 3. 공통 화면 체크

모든 페이지에서 아래를 먼저 확인한다.

- 헤더 제목이 `토마토 키우기`로 통일되어 있는가
- 프로필 버튼 위치가 페이지마다 어색하게 흔들리지 않는가
- 뒤로가기 버튼 크기, 위치, 테두리 스타일이 페이지마다 비슷한가
- 배경색, 벽돌 패턴, 흙 영역이 끊기지 않고 자연스럽게 이어지는가
- 버튼 hover, disabled 상태가 시각적으로 구분되는가
- 입력창 placeholder 색상과 실제 입력 텍스트 색상이 잘 보이는가
- 화면 가로폭이 줄어들었을 때 요소가 겹치지 않는가
- 모바일 폭에서도 버튼/텍스트가 잘리지 않는가

---

## 4. 페이지별 QA

### 4-1. 로그인 페이지

- 씨앗 봉투 레이아웃이 중앙에 잘 배치되는가
- `로그인` 버튼이 입력 전에는 비활성화되고, 입력 후에는 활성화되는가
- 잘못된 이메일/비밀번호 입력 시 에러 문구가 어색하지 않은가
- `씨앗 봉투 만들기` 버튼 클릭 시 회원가입 페이지로 이동하는가

### 4-2. 회원가입 페이지

- 프로필 이미지 등록/삭제가 정상 반영되는가
- 비밀번호 확인 불일치 시 에러가 바로 보이는가
- 닉네임 규칙 위반 시 문구가 잘 보이는가
- 가입 성공 후 로그인 페이지로 자연스럽게 이동하는가

### 4-3. 게시글 목록 페이지

- 상단 소개 카드가 기존 디자인과 같은 흐름으로 보이는가
- `토마토 심기` 버튼과 `내 토마토 밭 보기` 버튼 크기/정렬이 맞는가
- 게시글 카드 간 간격이 일정한가
- 게시글 카드에서 제목, 좋아요, 댓글, 조회수, 날짜가 읽기 쉬운가
- 게시글 썸네일이 있을 때와 없을 때 카드 높이가 크게 깨지지 않는가

### 4-4. 내 토마토 밭 페이지

- 내 게시글만 필터링되어 보이는가
- 상단 문구가 전체 목록 페이지와 구분되게 바뀌는가
- `전체 토마토 보기` 버튼으로 정상 이동하는가

### 4-5. 게시글 상세 페이지

- 제목, 작성자, 날짜, 본문, 이미지가 자연스럽게 배치되는가
- 작성자 본인일 때만 `수정`, `삭제` 버튼이 보이는가
- 이미지가 없는 게시글은 빈 박스 없이 자연스럽게 보이는가
- 좋아요/조회수/댓글 수 카드 높이와 간격이 일정한가
- 댓글 입력창이 물방울 카드처럼 잘 보이는가
- 댓글 버튼은 입력이 있을 때만 활성화되는가
- 댓글 수정 상태에서 textarea와 저장/취소 버튼이 어색하지 않은가

### 4-6. 게시글 작성 페이지

- 봉투형 카드 레이아웃이 자연스럽게 중앙 정렬되는가
- 제목, 내용, 이미지 입력 순서가 한눈에 들어오는가
- 이미지 선택 시 파일명이 정상 반영되는가
- 버튼 비활성/활성 상태가 명확한가
- 등록 성공 후 상세 페이지로 이동하는가

### 4-7. 게시글 수정 페이지

- 게시글 작성 페이지와 같은 톤으로 보이는가
- `내 토마토 다듬기` 제목이 어색하지 않은가
- 기존 제목/내용/이미지가 잘 불러와지는가
- 변경사항이 없을 때 저장이 막히는가
- 수정 후 상세 페이지에 변경 내용이 바로 반영되는가

### 4-8. 프로필 수정 페이지

- 프로필 카드가 중앙에서 안정적으로 보이는가
- 프로필 사진 위 장착 아이템 배지가 어색하지 않은가
- 성장 단계, 햇빛, 내 토마토 카드가 균등한가
- `내 토마토 밭 보기` 버튼이 전체 폭에서 어색하지 않은가
- 아이템 카드 상태가 아래처럼 구분되는가
  - 장착 중
  - 보유 중
  - 구매 가능
  - 구매 불가능
- `수정하기`, `비밀번호 수정`, `로그아웃` 버튼 간격이 일정한가
- 토스트 메시지가 너무 위/아래로 치우치지 않는가

### 4-9. 비밀번호 수정 페이지

- 비밀 씨앗 보관함 카드 레이아웃이 자연스러운가
- 현재 비밀번호/새 비밀번호/새 비밀번호 확인 순서가 잘 보이는가
- 비밀번호 규칙 문구가 너무 길거나 깨지지 않는가
- 성공 후 토스트가 뜨고 메인 흐름으로 돌아가는가

---

## 5. 기능 연결 QA

### 회원

- 회원가입 성공
- 회원가입 실패
  - 중복 이메일
  - 잘못된 형식
- 로그인 성공
- 로그인 실패
- 로그아웃 정상 동작

### 게시글

- 게시글 작성 성공
- 게시글 작성 실패
- 게시글 상세 조회
- 게시글 수정 성공
- 게시글 삭제 성공
- 본인 글만 수정/삭제 가능

### 댓글

- 댓글 작성 성공
- 댓글 수정 성공
- 댓글 삭제 성공
- 본인 댓글만 수정/삭제 가능

### 좋아요 / 조회수

- 좋아요 추가/취소가 즉시 반영되는가
- 상세와 목록의 숫자가 크게 어긋나지 않는가
- 조회수가 상세 진입 시 의도대로 증가하는가

### 프로필 / 아이템

- 닉네임 수정 성공
- 프로필 이미지 수정 성공
- 햇빛 수치 반영
- 아이템 구매 성공
- 장착 성공
- 장착 해제 성공
- 구매 불가능 아이템 버튼이 비활성화되는가

---

## 6. 반응형 체크

최소한 아래 3개 폭에서 확인한다.

- 데스크톱
- 태블릿
- 모바일

특히 아래를 본다.

- 헤더 제목이 너무 줄어들지 않는가
- 버튼 두 개가 한 줄에서 깨지지 않는가
- 게시글 카드 썸네일/텍스트가 겹치지 않는가
- 프로필 아이템 카드가 모바일에서 한 줄씩 자연스럽게 내려오는가
- 긴 닉네임이나 긴 파일명이 박스를 밀어내지 않는가

## 8. 최종 판정 기준

아래 세 가지가 모두 만족되면 최종 완료로 본다.

- 화면이 기존 HTML/CSS 버전과 비교했을 때 분위기와 구조가 크게 다르지 않다
- 주요 기능이 백엔드와 연결된 상태에서 정상 동작한다
- 모바일 폭에서도 레이아웃이 무너지지 않는다

---

## 9. 회고에 적으면 좋은 내용

최종 QA 후 회고에는 아래를 적으면 좋다.

- React로 바꾸면서 가장 많이 달라진 구조가 무엇이었는지
- HTML/CSS를 JSX로 옮길 때 가장 헷갈렸던 부분
- 상태 관리 때문에 편해진 점
- 반대로 기존 정적 페이지보다 더 신경 써야 했던 점
- 디자인 유지와 기능 연결 중 어느 쪽이 더 어려웠는지
