# 기술 고도화 정리

## 1. 프로젝트 개요

`토마토 키우기`는 사용자가 자신의 하루를 일기처럼 기록하고, 게시글을 작성할 때마다 토마토를 키워나가는 콘셉트의 커뮤니티형 다이어리 서비스이다. 단순 게시판 기능에서 끝나지 않고, 배포 환경 구성, Docker 기반 운영 구조, 검색, 댓글, 프로필, 아이템 보상 시스템, UI/UX 개선을 진행하여 실제 서비스처럼 사용할 수 있는 형태로 고도화했다.

## 2. 배포 및 인프라 고도화

### EC2 단일 인스턴스 배포

React 프론트엔드와 Spring Boot 백엔드를 AWS EC2 1대에 직접 배포했다. EC2 내부에 Java, Node.js, pnpm, Git, Nginx를 설치하고, React 빌드 결과물을 Nginx로 서빙하며 API 요청은 Spring Boot 서버로 전달하도록 구성했다.

주요 환경:

- Region: ap-northeast-2, Seoul
- OS: Ubuntu 26.04 LTS
- Instance type: t3.micro
- Storage: EBS 20 GiB
- Runtime: Java 21, Node.js 20, pnpm
- Reverse Proxy: Nginx

### Nginx 리버스 프록시 구성

초기 배포 과정에서 `/posts`, `/comments`, `/users` 요청이 프론트엔드 정적 서버로 전달되어 `405 Not Allowed` 오류가 발생했다. 이를 해결하기 위해 Nginx에서 화면 요청과 API 요청을 분리했다.

- 화면 요청: React frontend 컨테이너로 전달
- API 요청: Spring Boot backend 컨테이너로 전달
- `/api` prefix 기반 프록시 구조로 안정화

이 과정을 통해 프론트엔드와 백엔드가 같은 도메인에서 동작하면서도 내부적으로는 역할이 분리되는 구조를 만들었다.

### Docker Compose 통합 구성

React와 Spring Boot 각각에 멀티스테이지 Dockerfile을 작성하고, Docker Compose로 전체 서비스를 통합 실행하도록 구성했다.

- `backend`: Spring Boot 애플리케이션 컨테이너
- `frontend`: React 빌드 결과물을 Nginx로 서빙하는 컨테이너
- `nginx`: 외부 요청을 frontend/backend로 분기하는 리버스 프록시 컨테이너
- `backend-data`: H2 파일 DB 유지를 위한 Docker volume

Spring Boot Dockerfile은 Gradle 빌드용 이미지와 JRE 실행용 이미지를 분리했고, React Dockerfile은 Node 빌드 이미지와 Nginx 정적 서빙 이미지를 분리했다. 이를 통해 최종 이미지 크기와 실행 환경 의존성을 줄였다.

### EC2 리소스 문제 해결

t3.micro 환경에서 Docker 빌드 중 디스크와 메모리 부족 문제가 발생했다. 이를 해결하기 위해 다음 작업을 진행했다.

- EBS 볼륨을 20 GiB로 확장
- root filesystem resize
- 1 GiB Swap 추가
- 불필요한 Docker 이미지 및 캐시 정리
- host Nginx와 Docker Nginx의 80 포트 충돌 해결

이 과정에서 실제 클라우드 배포 환경에서는 애플리케이션 코드뿐 아니라 서버 리소스 관리도 중요하다는 점을 확인했다.

## 3. 기능 고도화

### 게시글 검색 기능

게시글 목록에서 제목과 내용을 기준으로 검색할 수 있는 기능을 추가했다. 단순히 프론트엔드에서 받아온 배열을 필터링하는 방식이 아니라, 백엔드 Repository 조건을 통해 DB 조회 조건에 검색어를 반영하는 구조로 구현했다.

이를 통해 데이터가 많아졌을 때도 프론트엔드가 모든 게시글을 받은 뒤 처리하는 방식보다 확장성 있는 구조를 만들 수 있다.

### 댓글 및 답글 기능

기존 댓글 기능에 답글 구조를 추가하는 방향으로 고도화를 진행했다. 댓글 도메인에 부모 댓글 관계를 추가하고, 댓글 응답 DTO에서도 답글 목록을 내려줄 수 있도록 구조를 확장했다.

이를 통해 단순 댓글 나열 방식에서 벗어나 게시글 상세 화면에서 사용자 간 대화 흐름을 표현할 수 있는 기반을 만들었다.

### 사용자 프로필 목록 기능

가입된 사용자들의 프로필을 따로 볼 수 있는 기능을 추가했다. 게시글 목록 화면에서 `토마토 밭 구경하기` 진입점을 두고, 사용자별 프로필 이미지, 닉네임, 보유 게시글 수 등을 확인할 수 있도록 확장했다.

이 기능은 단순 게시글 중심 서비스에서 사용자 중심 탐색이 가능한 서비스로 발전시키기 위한 고도화 작업이다.

### 아이템 보상 및 장착 시스템 개선

사용자가 활동을 통해 얻는 햇빛 보상과 아이템 구매/장착 기능을 개선했다.

- 아이템 구매 시 햇빛 차감 로직 오류 수정
- 프론트엔드와 백엔드의 아이템 가격 불일치 수정
- 아이템 장착 위치 CSS 조정
- 새싹 머리핀 이미지 배경 제거
- 토마토 머리핀, 밀짚모자, 앞치마, 장화 등 아이템별 표시 위치 개선

이를 통해 사용자가 기록 활동을 하면서 시각적 보상을 얻는 서비스 경험을 강화했다.

## 4. UI/UX 고도화

### 토마토 농장 콘셉트 강화

서비스 이름인 `토마토 키우기`에 맞춰 전체 UI를 토마토 농장 콘셉트로 개선했다. 게시글을 단순 카드가 아니라 토마토 형태로 보여주고, 게시글 이미지는 작은 나무 표지판에 표시되도록 구성했다.

주요 개선:

- 게시글 목록을 토마토 카드 형태로 변경
- 검색 영역을 농장 표지판 형태로 개선
- 게시글 이미지가 카드 내용과 겹치지 않도록 표지판 영역으로 분리
- 좋아요, 조회수, 댓글 수, 날짜, 작성자 정보를 토마토 카드 안에서 보기 쉽게 정리
- 작성자 아이콘과 닉네임 위치 조정

### 게시글 목록 정보 구조 개선

게시글 목록에서는 긴 본문을 모두 보여주지 않고, 사용자가 빠르게 게시글을 탐색할 수 있도록 핵심 정보 중심으로 배치했다.

- 제목 중심 표시
- 좋아요 수, 조회수, 댓글 수를 한눈에 확인
- 날짜 표시
- 작성자 프로필 아이콘과 닉네임 표시
- 상세 내용은 게시글 상세 페이지에서 확인

이를 통해 목록 화면의 가독성을 높이고, 토마토 카드 이미지와 텍스트가 겹치는 문제를 줄였다.

## 5. 오류 수정 및 안정화

배포와 기능 구현 과정에서 여러 오류를 발견하고 수정했다.

- 게시글 작성 시 `POST /posts`가 frontend Nginx로 들어가던 문제 해결
- 댓글 수정/삭제 요청이 Nginx에서 `405 Not Allowed`가 되던 문제 해결
- 조회수 증가 API가 실패할 때 상세 조회로 fallback 처리
- Docker Nginx upstream DNS 문제 해결
- `/api/posts` 라우팅 구조 안정화
- Base64 이미지 응답으로 인해 API 응답이 과도하게 커지는 문제 확인

특히 Nginx 라우팅 문제는 프론트엔드 오류처럼 보였지만, 실제 원인은 배포 환경의 프록시 설정이었다. 이를 해결하면서 운영 환경에서의 디버깅 경험을 쌓을 수 있었다.

## 6. HTTPS 적용 준비

HTTPS 적용을 위해 `sslip.io` 기반 임시 도메인을 사용하기로 했다. 별도 도메인을 구매하지 않고도 EC2 Public IP를 도메인 형태로 사용할 수 있어, Let's Encrypt 인증서 발급을 진행할 수 있다.

적용 예정 URL:

```text
https://13-125-50-220.sslip.io/posts
```

반영한 구성:

- Docker Nginx 443 포트 오픈
- `/etc/letsencrypt` 인증서 볼륨 연결
- HTTP 요청을 HTTPS로 redirect하는 Nginx 설정
- HTTPS 환경에서 `/api` 요청을 backend로 프록시

HTTPS 적용이 완료되면 포트폴리오에서 보안 배포 경험으로 설명할 수 있다.

## 7. S3 적용 예정

현재 게시글 이미지는 Base64 형태로 저장되거나 응답에 포함되면서 API 응답이 지나치게 커지는 문제가 있다. 이를 개선하기 위해 다음 고도화로 AWS S3 적용을 계획했다.

개선 방향:

- 이미지는 S3 버킷에 저장
- DB에는 이미지 파일 자체가 아니라 S3 URL만 저장
- React는 S3 URL을 통해 이미지를 표시
- API 응답 크기 감소
- DB 저장 부담 감소

포트폴리오 표현:

```text
게시글 이미지 저장 방식을 Base64 DB 저장에서 AWS S3 Object Storage 기반 URL 저장 구조로 개선하여 API 응답 크기와 DB 부하를 줄일 예정입니다.
```

## 8. 포트폴리오용 요약 문장

```text
React + Spring Boot 기반 다이어리 서비스를 AWS EC2 단일 인스턴스에 Docker Compose로 배포하고, Nginx 리버스 프록시를 통해 프론트엔드와 백엔드 요청을 분리했습니다. 또한 게시글 검색, 댓글 답글, 사용자 프로필 탐색, 아이템 보상 시스템, 토마토 농장 콘셉트 UI 개선을 진행하여 단순 CRUD 게시판을 실제 서비스형 프로젝트로 고도화했습니다.
```

```text
Docker 멀티스테이지 빌드, EC2 리소스 확장, Swap 설정, Nginx 라우팅 오류 해결, HTTPS 적용 준비까지 직접 수행하며 클라우드 배포 환경에서 발생하는 문제를 진단하고 해결한 경험을 쌓았습니다.
```

## 9. 향후 고도화 계획

우선순위에 따라 다음 작업을 진행할 수 있다.

1. HTTPS 인증서 발급 및 적용 완료
2. S3 기반 이미지 업로드 구조 적용
3. RDS 기반 MySQL/PostgreSQL 전환
4. 게시글/댓글 페이지네이션 적용
5. 사용자 프로필 공개 페이지 완성
6. 활동 보상 정책 테스트 코드 보강
7. GitHub Actions 기반 CI/CD 자동 배포 구성
