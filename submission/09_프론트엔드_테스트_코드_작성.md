# 프론트엔드 테스트 코드 작성

## 1. 작업 목적

프론트엔드 코드에도 테스트 코드를 추가해, 화면에서 자주 문제가 생길 수 있는 API 호출 로직과 UI 표시 로직을 자동으로 확인할 수 있게 했다.

이번 테스트는 새 라이브러리를 설치하지 않고 Node.js 기본 테스트 러너를 사용했다. 이유는 현재 프로젝트가 Docker 빌드에서 `pnpm install --frozen-lockfile`을 사용하고 있어서, 테스트 라이브러리를 추가하면 `pnpm-lock.yaml`까지 맞춰야 하고 배포 빌드가 깨질 위험이 있기 때문이다.

즉, 이번 단계에서는 배포 안정성을 유지하면서 바로 실행 가능한 테스트 기반을 먼저 만들었다.

## 4. API 테스트 작성

`frontend/src/lib/__tests__/api.test.js`에서는 API 요청 로직을 테스트했다.

확인한 내용:

- 로그인 응답에서 token과 user 정보를 정상적으로 정규화하는지 확인
- token이 없는 로그인 응답이면 `ApiError`를 발생시키는지 확인
- 게시글 검색 시 검색어를 URL query string으로 인코딩하는지 확인
- 인증 토큰이 있을 때 `Authorization: Bearer ...` 헤더가 붙는지 확인
- 검색어가 빈 값이면 `/posts`만 호출하는지 확인

핵심 코드:

```js
test("fetchPosts sends encoded keyword and bearer token", async () => {
  let requestedUrl = "";
  let requestedOptions = null;

  const restoreFetch = withMockFetch(async (url, options) => {
    requestedUrl = url;
    requestedOptions = options;
    return jsonResponse([{ id: 1, title: "비 오는 오후" }]);
  });

  try {
    const posts = await fetchPosts("token-123", " 비 오는 오후 ");

    assert.deepEqual(posts, [{ id: 1, title: "비 오는 오후" }]);
    assert.equal(
      requestedUrl,
      "http://localhost:8080/posts?keyword=%EB%B9%84%20%EC%98%A4%EB%8A%94%20%EC%98%A4%ED%9B%84",
    );
    assert.equal(requestedOptions.method, "GET");
    assert.equal(requestedOptions.headers.Authorization, "Bearer token-123");
  } finally {
    restoreFetch();
  }
});
```

## 5. UI 유틸 테스트 작성

`frontend/src/lib/__tests__/ui.test.js`에서는 화면 표시용 유틸 함수를 테스트했다.

확인한 내용:

- 좋아요, 조회수, 댓글 수 같은 숫자가 `1k`, `10k`, `100k` 형태로 줄여 표시되는지 확인
- 날짜 값이 비어 있거나 잘못된 값이어도 화면이 깨지지 않도록 처리되는지 확인
- 이미지 후보 값이 `http`, `https`, `data:image` 형식일 때만 화면에 표시되도록 필터링되는지 확인
- 프로필 이미지가 없을 때 닉네임 첫 글자 fallback이 만들어지는지 확인

핵심 코드:

```js
test("formatCount keeps post card counts compact", () => {
  assert.equal(formatCount(0), "0");
  assert.equal(formatCount(999), "999");
  assert.equal(formatCount(1000), "1k");
  assert.equal(formatCount(10000), "10k");
  assert.equal(formatCount(100000), "100k");
});
```

## 6. 게시글 목록 로직 테스트 보강

`frontend/src/lib/posts.js`를 새로 만들고, 게시글 목록 화면에서 사용하던 주요 표시 로직을 테스트 가능한 함수로 분리했다.

검증한 내용:

- 검색어 앞뒤 공백 제거
- `내 토마토 밭 보기`에서 현재 사용자가 작성한 게시글만 필터링
- 게시글 카드에 표시할 제목, 좋아요, 조회수, 댓글 수, 작성자, 이미지 값을 안전하게 정리

핵심 코드:

```js
test("filterPostsByOwner keeps only posts written by the current user", () => {
  const posts = [
    { id: 1, userId: 7, title: "내 글" },
    { id: 2, authorId: "7", title: "내 글 2" },
    { id: 3, userId: 9, title: "남의 글" },
  ];

  assert.deepEqual(
    filterPostsByOwner(posts, { id: 7 }).map((post) => post.id),
    [1, 2],
  );
});
```

## 7. 사용자 목록 로직 테스트 보강

`frontend/src/lib/farmers.js`를 새로 만들고, 가입한 사용자 목록 화면에서 사용하던 정렬과 아이템 이름 변환 로직을 테스트했다.

검증한 내용:

- 현재 로그인한 사용자를 목록 맨 앞으로 정렬
- 다른 사용자는 작성한 게시글 수가 많은 순서로 정렬
- 장착 아이템 코드가 화면에 보여줄 한글 이름으로 변환되는지 확인
- 빈 값이 들어와도 화면이 깨지지 않도록 빈 배열 반환

핵심 코드:

```js
test("sortFarmersForCurrentUser puts my profile first and sorts others by post count", () => {
  const farmers = [
    { id: 2, nickname: "belle", myPostCount: 3 },
    { id: 1, nickname: "0000", myPostCount: 1 },
    { id: 3, nickname: "seed", myPostCount: 7 },
  ];

  assert.deepEqual(
    sortFarmersForCurrentUser(farmers, { id: 1 }).map((farmer) => farmer.nickname),
    ["0000", "seed", "belle"],
  );
});
```

## 8. 테스트를 위해 조정한 부분

`frontend/src/lib/api.js`의 API base URL 선언을 테스트 환경에서도 안전하게 import할 수 있도록 수정했다.

변경 전:

```js
const API_BASE_URL = import.meta.env.VITE_API_BASE_URL ?? "http://localhost:8080";
```

변경 후:

```js
const API_BASE_URL = import.meta.env?.VITE_API_BASE_URL ?? "http://localhost:8080";
```

Vite 실행 환경에서는 기존처럼 `VITE_API_BASE_URL`을 사용하고, Node 테스트 환경에서는 기본값인 `http://localhost:8080`을 사용한다.

또한 `PostsPage`, `PostCard`, `FarmersPage`에 직접 들어 있던 일부 계산 로직을 `src/lib` 함수로 분리했다. 화면 코드는 더 가벼워지고, 핵심 로직은 테스트로 검증할 수 있게 됐다.

## 9. 의미

이번 테스트는 전체 화면 테스트까지 포함한 단계는 아니지만, 현재 프로젝트에서 중요한 프론트엔드 로직을 자동으로 검증할 수 있는 기반을 만들었다는 점에서 의미가 있다.

특히 검색 기능, 인증 응답 처리, 이미지 표시 조건, 숫자 표시 형식, 내 게시글 필터링, 사용자 목록 정렬은 실제 화면 오류로 이어지기 쉬운 부분이므로 테스트 대상으로 우선 선정했다.
