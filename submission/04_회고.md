# 회고

이번 과제에서는 React와 Spring Boot 프로젝트를 EC2에 직접 배포하고, 이후 Docker Compose 기반 배포 구조로 확장했다. 처음에는 로컬 Mac 환경과 EC2 Ubuntu 환경을 헷갈려서 명령어를 잘못 실행하는 문제가 있었다. 예를 들어 Mac에서는 `apt` 명령이 동작하지 않는데 EC2에서 실행해야 할 명령을 로컬에서 실행한 적이 있었다. 이 과정을 통해 배포 작업에서는 현재 접속한 환경을 먼저 확인하는 습관이 중요하다는 것을 배웠다.

Nginx 리버스 프록시를 구성하면서 프론트엔드 라우팅과 백엔드 API 라우팅을 분리하는 것이 중요하다는 점도 알게 되었다. 처음에는 `/posts` 요청이 React 정적 서버로 들어가면서 `405 Not Allowed`가 발생했다. 이후 Nginx 설정에서 `/posts`, `/comments`, `/users` 요청을 Spring Boot 백엔드로 넘기도록 수정하면서 문제가 해결되었다.

Docker Compose로 전환하는 과정에서는 실제 서버 리소스 문제가 크게 드러났다. EC2의 기본 디스크 용량이 부족해서 Docker 이미지 빌드 중 `no space left on device` 오류가 발생했고, Gradle 빌드 중에는 메모리 부족으로 빌드가 멈추기도 했다. 이를 해결하기 위해 EBS 볼륨을 20 GiB로 확장하고, 1 GiB Swap을 추가했다. 로컬 개발 환경에서는 잘 드러나지 않던 서버 운영 환경의 제약을 직접 경험할 수 있었다.

프로젝트 기능 면에서는 게시글 조회수, 댓글 수정, 게시글 작성, 아이템 구매 가격 차감 등 배포 후 실제 브라우저에서 테스트하면서 발견한 문제를 수정했다. 특히 아이템 가격이 프론트엔드와 백엔드에서 서로 다르게 관리되어 잘못 차감되는 문제가 있었고, 이를 백엔드 가격 기준으로 통일하면서 해결했다. 이 경험을 통해 중요한 데이터는 한쪽을 기준으로 관리하고, 프론트엔드는 서버 응답을 우선 사용해야 한다는 점을 배웠다.

전체적으로 단순히 코드를 작성하는 것보다, 실제 서버에서 실행하고 브라우저로 테스트하면서 문제를 발견하고 해결하는 과정이 더 중요하다는 것을 느꼈다. 이번 과제를 통해 EC2, Nginx, Docker Compose, 서버 리소스 관리, 배포 후 디버깅 흐름을 한 번에 경험할 수 있었다.
