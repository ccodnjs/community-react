# 작업 과정

## 1. EC2 직접 배포

처음에는 EC2 1대에 필요한 런타임을 직접 설치한 뒤 React와 Spring Boot를 실행했다.

설치한 주요 패키지:

- Java 21
- Node.js 20.20.2
- pnpm 10.34.5
- Git
- Nginx

React 프로젝트는 `pnpm build`로 빌드했고, 빌드 결과물은 `/var/www/community`에 배치했다. 이후 host Nginx에서 정적 파일을 서빙하고, API 요청은 Spring Boot 서버로 프록시하도록 구성했다.

## 2. Nginx 리버스 프록시 구성

초기 배포에서는 `/posts`, `/comments`, `/users` 같은 API 요청이 React 정적 서버로 들어가면서 `405 Not Allowed`가 발생했다. 이를 해결하기 위해 Nginx에서 API 경로를 Spring Boot 백엔드로 넘기도록 설정했다.

Docker Compose 환경의 Nginx 라우팅:

```nginx
location ~ ^/(posts|comments|users|h2-console)(/|$) {
    set $backend "backend";
    proxy_pass http://$backend:8080;
}

location / {
    set $frontend "frontend";
    proxy_pass http://$frontend:80;
}
```

## 3. Dockerfile 멀티스테이지 빌드

Spring Boot와 React 모두 멀티스테이지 Dockerfile을 작성했다.

Spring Boot:

- Gradle JDK 이미지에서 `bootJar` 빌드
- JRE 이미지로 jar 파일만 복사해 실행

React:

- Node 이미지에서 pnpm install 및 build 실행
- Nginx 이미지로 `dist` 결과물만 복사해 정적 서빙

## 4. Docker Compose 통합 구성

Docker Compose로 backend, frontend, nginx를 한 번에 실행하도록 구성했다.

```bash
ssh -i ~/Desktop/11/community-key.pem ubuntu@13.125.50.220
cd ~/community-react
git pull origin main
sudo docker compose build backend frontend
sudo docker compose up -d --force-recreate backend frontend nginx
sudo docker compose ps
```

현재 실행 컨테이너:

```text
community-backend   Spring Boot backend   8080/tcp
community-frontend  React frontend        80/tcp
community-nginx     Reverse proxy         0.0.0.0:80->80/tcp
```

## 5. 배포 중 해결한 문제

- Mac 로컬 환경과 EC2 Ubuntu 환경을 혼동해 `apt` 명령이 로컬에서 실행되는 문제가 있었다.
- EC2 디스크가 부족해 Docker build가 실패했고, EBS를 20 GiB로 확장한 뒤 filesystem을 resize했다.
- Docker build 중 메모리가 부족해 Gradle 빌드가 멈췄고, 1 GiB Swap을 추가했다.
- host Nginx와 Docker Nginx가 둘 다 80 포트를 사용하려 해서 host Nginx를 중지하고 비활성화했다.
- Docker Nginx에서 backend upstream을 찾지 못하는 문제가 있어 Docker DNS resolver 설정을 추가했다.
- 게시글 작성 API가 frontend 컨테이너로 들어가 `405 Not Allowed`가 발생했고, API 경로 정규식을 수정해 해결했다.

## 6. 프로젝트 고도화
